# Daily Activity Review Bot

A local daemon and CLI that tracks which apps and windows you use throughout the
day, aggregates that usage into a structured summary at day's end, and writes a
short narrative report ("what I did today") generated by a free LLM API.

Raw low-level data (window titles, shell commands) never leaves the machine.
Only a pre-scrubbed, aggregated summary is sent to the LLM.

## Features

- Polls the active window (app + window title) every few seconds and stores
  debounced intervals in a local Postgres database.
- Ingests higher-signal events when available:
  - Shell history (append-only tail of `.zsh_history` / `.bash_history` with
    timestamps).
  - Git commits across a configured list of repositories (via `git log`).
- Produces a single structured, redacted JSON object for the day: total active
  time, time per category, top apps, git commits, and context-switch density.
- Sends that JSON to a free LLM (Groq by default) and renders a 3-5 sentence
  narrative, a focus-vs-scattered verdict, and a bulleted list of shipped work.
- Outputs to the terminal and optionally writes a markdown file to
  `~/daily-reviews/YYYY-MM-DD.md`.
- `bun run report` works standalone against any day already in Postgres,
  independent of whether the tracker is running.

## Privacy model

- Keystrokes, screenshots, and clipboard content are never captured.
- Full window titles with sensitive content stay in the local Postgres database.
- Browser window titles are redacted before they leave the machine: the title is
  truncated at the first ` - ` separator, and bare URLs are reduced to their
  domain. Non-browser titles are kept as-is.
- The only payload sent to the LLM is the aggregated, redacted daily summary.

## Requirements

- [Bun](https://bun.sh) 1.x
- PostgreSQL (local instance) — tested against PostgreSQL 18 on Windows and any
  recent version on macOS/Linux
- A free [Groq](https://console.groq.com) API key for report generation
  (optional if you only want to track/migrate)

## Setup

1. Install Bun, then install dependencies:

   ```sh
   bun install
   ```

2. Make sure Postgres is running. Create a database (the default `DATABASE_URL`
   below assumes one named `activity`):

   ```sh
   psql -U postgres -c "CREATE DATABASE activity;"
   ```

3. Copy the example environment file and fill it in:

   ```sh
   cp .env.example .env
   ```

   At minimum, set `DATABASE_URL` and `GROQ_API_KEY`. Bun auto-loads `.env`
   from the project root.

4. Apply the SQL migration to create the schema:

   ```sh
   bun run migrate
   ```

## Environment variables

All configuration is read from the environment via Effect `Config`. `Bun`
loads them from `.env` automatically.

| Variable              | Required | Default                                    | Description                                                                       |
| --------------------- | -------- | ------------------------------------------ | --------------------------------------------------------------------------------- |
| `DATABASE_URL`        | yes      | —                                          | Postgres connection string, e.g. `postgresql://user:pass@localhost:5432/activity` |
| `GROQ_API_KEY`        | for report | —                                        | Groq API key. Only needed for `bun run report`.                                    |
| `GROQ_MODEL`          | no       | `llama-3.3-70b-versatile`                  | Groq chat model used for summarization.                                            |
| `GROQ_ENDPOINT`       | no       | `https://api.groq.com/openai/v1/chat/completions` | Groq OpenAI-compatible endpoint.                                            |
| `REPO_PATHS`          | no       | empty                                      | Comma-separated paths to git repositories to include commit history from.          |
| `POLL_INTERVAL`       | no       | `5 seconds`                                | Active-window poll interval (Effect duration, e.g. `5 seconds`, `2000 millis`).    |
| `SHELL_HISTORY_PATH`  | no       | empty                                      | Path to a zsh/bash history file to tail for shell commands.                        |
| `REVIEW_DIR`          | no       | `~/daily-reviews`                          | Directory where `YYYY-MM-DD.md` report files are written.                          |
| `MIGRATIONS_DIR`      | no       | `migrations`                               | Directory containing the `<id>_<name>.sql` migration files.                        |

## Commands

| Command                 | Description                                                          |
| ----------------------- | -------------------------------------------------------------------- |
| `bun run tracker`       | Start the active-window tracking daemon (runs until stopped).        |
| `bun run report`        | Produce today's report (aggregate + LLM summary + markdown file).    |
| `bun run report --date YYYY-MM-DD` | Produce a report for a specific local day.                    |
| `bun run migrate`       | Apply pending SQL migrations.                                        |
| `bun run typecheck`     | Run the TypeScript compiler in no-emit mode.                         |
| `bun test`              | Run the unit test suite.                                             |

## Daily workflow

```sh
bun run migrate     # once, to create the schema
bun run tracker     # leave running while you work
bun run report      # end of day, generates the narrative and markdown file
```

`report` needs `GROQ_API_KEY` and works for any day already stored in Postgres,
so you can run it later even if the tracker is no longer running.

## How it works

The application is split into four subsystems:

1. **Tracker daemon** (`src/tracker/`) — polls the active window on an interval
   and only writes a row when the active app/title changes, producing
   `{ start, end, app, title }` intervals instead of raw poll ticks. It also
   tails shell history for command events. Data lands in the `activity.event`
   table.

2. **Aggregator** (`src/aggregate/`) — groups intervals by app and category
   (`code editor`, `terminal`, `browser`, `comms`, `other`, from a static
   app-to-category map), sums durations, collects top apps, redacts browser
   titles, and computes context-switch density (app switches per hour).

3. **Summarizer** (`src/llm/`) — sends the aggregated JSON to Groq with a
   structured-output prompt asking for a narrative, a focus-vs-scattered
   verdict, and a shipped-work list. Retries use exponential backoff with
   jitter.

4. **Output** (`src/report/`) — renders the result to the terminal and writes
   the markdown file to the review directory.

### Database schema

Migrations are plain SQL files named `<id>_<name>.sql` in `migrations/`, applied
by a forward-only migrator that records applied ids in the `effect_sql_migrations`
table. The initial migration creates:

```
activity.event (
  id        BIGSERIAL PRIMARY KEY,
  start_at  TIMESTAMPTZ NOT NULL,
  end_at    TIMESTAMPTZ NOT NULL,
  app       TEXT NOT NULL,
  title     TEXT NOT NULL DEFAULT '',
  kind      TEXT NOT NULL DEFAULT 'window' CHECK (kind IN ('window', 'shell')),
  command   TEXT
)
```

## Platform support

The window sampler is behind a platform-specific layer:

- **macOS** (primary target): `osascript`/AppleScript via System Events.
- **Linux X11**: `xdotool getactivewindow` (with `swaymsg` as a future Wayland
  option).
- **Windows**: PowerShell with a `user32 GetForegroundWindow` P/Invoke snippet.
- **Unknown platforms**: a stub layer that fails with a typed error.

## Auto-starting the tracker (macOS)

### launchd

Create `~/Library/LaunchAgents/com.example.daily-activity.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.example.daily-activity</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/you/.bun/bin/bun</string>
    <string>run</string>
    <string>tracker</string>
  </array>
  <key>WorkingDirectory</key><string>/path/to/ai-task-update</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict>
</plist>
```

Then:

```sh
launchctl load ~/Library/LaunchAgents/com.example.daily-activity.plist
```

### cron

```sh
crontab -e
# start the tracker at 8am daily (idempotent, or kill the previous instance first)
0 8 * * * cd /path/to/ai-task-update && bun run tracker
```

A daily `bun run report` can be scheduled the same way:

```sh
30 18 * * * cd /path/to/ai-task-update && bun run report
```

## Troubleshooting

- **`PgClient: Failed to connect` / password authentication failed** — the
  `DATABASE_URL` credentials do not match your Postgres instance. Verify with
  `psql -U <user> -h localhost -p 5432 -d <db>`.
- **`database "activity" does not exist`** — create the database first
  (see Setup).
- **`undefined is not an object (evaluating '_.default')`** — the migrator's
  loader contract was violated. Each migration entry must wrap the migration
  effect in `Effect.succeed(...)` so its success value is itself an Effect
  (see `src/db.ts`).
- **No report summary** — `report` requires a valid `GROQ_API_KEY`; `tracker`
  and `migrate` run without one.
- **No activity recorded** — the tracker only writes on app/title changes and
  the report is scoped to a local day; confirm you ran `bun run tracker`
  during the target day and that `REPO_PATHS`/`SHELL_HISTORY_PATH` are set if
  you expect those signals.

## Non-goals

- No screenshots, keystroke content, or clipboard capture.
- No cross-device sync.
- No web UI — CLI/terminal output only.
