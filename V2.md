# Version 2 Roadmap

Prioritized improvement list for the next major version, roughly in impact
order.

## Signal quality (biggest wins)

1. **Better titles** — Windows/macOS window titles are often empty or one
   character (as seen in practice). Use per-app richer sources instead of the
   raw window title:
   - Chrome/Edge via the Chrome DevTools Protocol or a small browser extension.
   - Native APIs on macOS (`NSWorkspace` / Accessibility) instead of `osascript`.
   - This is the single biggest report-quality lever.

2. **Editor file tracking** — capture the file path from the IDE window title
   (VS Code already encodes `path - app` in its title), and attribute time to a
   file or project rather than only to the app.

3. **Browser URL history** — read tab URLs from the browser's history database
   instead of the window title, then classify time by domain/project. Raw URLs
   stay local; only the domain/project label goes to the LLM.

## Smarter aggregation

4. **Session/flow detection** — cluster the interval timeline into "work
   sessions" separated by idle gaps, so the narrative can report "three
   deep-work blocks" instead of raw totals.

5. **Per-repo/project time** — attribute time to a repository by matching
   editor window-title file paths against `REPO_PATHS`, giving per-project
   breakdowns alongside per-app ones.

6. **Idle detection** — stop the clock when there is no input for N minutes
   (screen-saver events or input hooks), so "active time" is honest and does
   not count a locked/idle machine.

## Output

7. **Better summaries** — stream longer multi-paragraph summaries, add
   weekly/monthly rollups, support ad-hoc trend queries ("what did I focus on
   last week?"), and expose a plain-JSON mode for scripting.

8. **Retention and pruning** — a cleanup job (for example keep the last 90
   days) so the local database does not grow without bound.

## Infrastructure

9. **Cross-device sync** (a v1 non-goal) — sync only the redacted aggregate so
   reports can be read from a phone or a second machine without leaking raw
   data.

10. **Wayland sampler** — finish the Linux story with `swaymsg`/Wayland support,
    and add a Docker Compose file for Postgres so setup is one command.

11. **Test coverage** — unit tests for the shell-history parser and the
    redaction edge cases, which are currently missing.
